# 라즈베리파이 5 — 체온 외곽선 추종 MLC 제어 (1행 / 리프 4장)

열화상으로 사람의 체온 영역을 찾고, 광학 영상으로 그 경계를 다듬어서,
리프 4장이 각자 얼마나 열려 있어야 하는지 mm 로 계산해 아두이노에 보냅니다.

```
[Lepton 3.5 / PT3] --USB(Y16 온도)--┐
                                    ├--> [run_row1.py] --USB Serial--> [Arduino UNO]
[Camera Module 3]  --CSI(picamera2)-┘     조사야 격자 정합             AMLA_4CH_Positioning
                                          체온 마스크 + 광학 엣지            L298N x2
                                          -> SET m1 m2 m3 m4               액츄에이터 x4
```

MLC 최종형은 2행 4열(리프 8장)이지만 아두이노가 한 대뿐이라 지금은 **상단 뱅크 4장**만
구동합니다. 두 번째 아두이노를 붙이면 `--bank bottom --port /dev/ttyACM1` 로 한 대 더
띄우면 됩니다. 계산은 영상을 위아래로 뒤집어 같은 코드를 그대로 씁니다.

USB 로 파이에 옮겨 꽂아도 됩니다.

## 0. 파일을 파이로 옮기기

이 폴더(`MLC_row1`)를 통째로 파이의 홈으로 옮깁니다. 방법은 아무거나 됩니다.

**PowerShell 에서 (파이에 SSH 가 켜져 있을 때)**

```powershell
scp -r "MLC_row1" ict@ict.local:~/
```

SSH 가 꺼져 있으면 파이에서 `sudo raspi-config` → Interface Options → SSH → Enable.

**RealVNC Viewer 로 (SSH 없이)** — 뷰어 위쪽 툴바의 파일 전송 아이콘으로 폴더를 끌어다 놓습니다.

**USB 메모리로** — 가장 확실합니다.

옮긴 뒤 파이에서:

```bash
cd ~/MLC_row1 && ls
```

`run_row1.py` 가 보이면 됩니다. 앞으로 모든 명령은 **이 폴더 안에서** 실행하세요.
`~/Desktop` 에서 실행하면 `No such file or directory` 가 납니다.

## 2. 처음 실행 순서

순서를 지켜야 액츄에이터가 벽을 때리지 않습니다.

### (1) 장치가 보이는가

```bash
python3 run_row1.py --list
rpicam-hello --list-cameras
```

열화상은 `/dev/video*` 중 `uint16 (122, 160)` 또는 `(120, 160)` 으로 잡히는 쪽입니다.
PureThermal 은 노드를 두 개 만드는데 영상이 나오는 쪽(보통 낮은 번호)을 씁니다.
광카메라는 CSI 라 `/dev/video*` 목록으로 판단하면 안 되고 `rpicam-hello` 로 봅니다.

### (2) 아두이노만 따로 확인 — 모터가 도는지 눈으로

**포트 이름부터 확인하세요.** 이 프로젝트의 아두이노는 정품이 아니라 **CH340 칩을 쓰는
호환보드**라서 `/dev/ttyACM0` 이 아니라 **`/dev/ttyUSB0`** 으로 잡힙니다.
`ls /dev/ttyACM*` 만 보고 "아두이노가 안 붙었다"고 판단하면 안 됩니다.

```bash
ls /dev/ttyUSB* /dev/ttyACM*
python3 mlc_driver.py /dev/ttyUSB0
```

아무것도 안 보이면 USB 인식 자체가 안 된 것입니다. 꽂았다 빼면서:

```bash
dmesg | tail -20
```

`idVendor=1a86, idProduct=7523` / `ch341-uart converter now attached to ttyUSB0`
가 보이면 정상입니다. 아무 반응이 없으면 **충전 전용 USB 케이블**을 의심하세요.
전원 LED 는 켜지는데 데이터선이 없어서 인식이 안 되는, 겉보기로 구분 안 되는 함정입니다.

채널별로 하나씩 확인하려면:

```bash
python3 mlc_driver.py /dev/ttyUSB0 --test
```

`PING → CFG → HOME → 20mm → CH1 40mm → HOME` 순서로 돕니다.
**여기가 안 되면 카메라 쪽은 볼 필요도 없습니다.** 아래 "문제 해결" 로 가세요.

### (3) 조사야 4점 보정 — 이 프로젝트에서 가장 중요한 단계

```bash
python3 run_row1.py --calib
```

두 카메라는 서로 다른 자리에 붙어 있어 그냥 겹치면 몇 cm 씩 어긋납니다. 조사야가
95×115mm 밖에 안 되니 보정 없이는 융합 판정이 의미가 없습니다.

1. 콜리메이터를 완전히 개방하고 라이트 필드를 켭니다
2. 빛의 사각형 네 귀퉁이를 테이프로 표시합니다
3. 그 자리에 **따뜻한 표식**을 하나씩 올려둡니다 (핫팩, 따뜻한 물 담은 병뚜껑, 손으로 데운 동전)
4. 열화상 화면에서 좌상 → 우상 → 우하 → 좌하 순으로 클릭 → Enter
5. **표식을 그대로 둔 채** 광학 화면에서 같은 네 점을 클릭 → Enter
6. 겹쳐 보여주는 확인 화면에서 두 영상의 표식이 겹치면 성공

결과는 `mlc_field_calib.json` 에 저장됩니다. 카메라를 옮기면 다시 하세요 (2분).

### (4) 모터 없이 화면만

```bash
python3 run_row1.py --no-serial
```

사람이 초록 윤곽으로 잡히는지, 노란 외곽선이 몸을 따라가는지, 파란 리프 선이
사람 위쪽에 자리잡는지 봅니다. 잘 안 잡히면 `[` `]` 로 최저 체온을, `,` `.` 으로
최고 체온을 조절합니다. 옷 입은 사람의 표면 온도는 28~33도로 생각보다 낮습니다.

### (5) 실제 운전

```bash
python3 run_row1.py --port auto
```

**모터는 꺼진 채로 시작합니다.** 화면을 보고 계산이 멀쩡한 걸 확인한 다음
`SPACE` 로 켜세요. 처음부터 켜려면 `--motor-on`.

## 4. 안전 설계 — 어느 방향이 안전한가

| 상황 | 결과 |
|---|---|
| 액츄에이터 0 mm (홈) | 리프 **완전히 닫힘** = 완전 차폐 |
| 그 열에 사람이 안 보임 | 0 mm = 완전 차폐 |
| 파이가 죽거나 USB 가 빠짐 | 아두이노 워치독(3초)이 0 mm 로 = 완전 차폐 |
| 프로그램 정상 종료 | 0 mm 로 되돌린 뒤 종료 |

즉 **판단이 서지 않으면 닫는 쪽**입니다. 열려 있으면 사람이 피폭되지만
닫혀 있으면 영상만 못 얻습니다. 프로그램 시작 시 펌웨어에 `LIM 57.5` / `FS 0.0` /
`WD 1` 을 걸어 이 정책을 아두이노 쪽에도 심습니다.

## 5. 계산이 실제로 하는 일

조사야 격자는 **230 × 190 px = 115 × 95 mm, 0.5 mm/px** 입니다.
가로를 4등분한 것이 리프 4장이고, 가로 중심선이 상하 뱅크가 맞물리는 자리입니다.

1. **체온 마스크** — 30~41 ℃ 를 인체로 보고 열림/닫힘 연산으로 노이즈를 정리한 뒤
   **15 mm² 보다 작은 덩어리만** 버립니다.
   *가장 큰 덩어리만 남기지 않습니다* — 손가락·팔·어깨는 열화상에서 몸통과 끊어진
   별개 덩어리로 잡히는 일이 흔하고, 그걸 버리면 그 위로 리프가 그대로 내려옵니다
2. **외곽선 프로파일** — 가로 위치마다 인체가 시작되는 행을 찾습니다.
   세로로 3픽셀 이상 이어진 곳만 인정해 점 노이즈를 거릅니다
3. **광학 융합** — 그 경계를 ±6 mm 안의 광학 엣지로 스냅합니다.
   Lepton 은 격자에서 1픽셀이 1.2mm 인데 광학은 0.15mm 를 봅니다
   - *무엇이 사람인가*는 열화상이 정하고, *경계가 정확히 어디인가*만 광학이 다듬습니다
   - 창 안에서 그냥 최댓값을 고르면 안 됩니다. 어깨 옆구리처럼 외곽이 거의 수직인
     자리에서는 봉우리가 없어 탐색창 끝으로 밀립니다(실측 ±6 mm 튐). 그래서
     **거리 가중 + 돌출도 검사**를 넣었습니다. 실측 이동량은 ±2 mm 로 제한됩니다
4. **리프별 개방 거리** — 각 열에서 인체의 가장 윗점까지 열고 마진 5 mm 를 더합니다.
   0 ~ 57.5 mm 로 자릅니다
5. **평활 (비대칭)** — **여는 방향은 즉시, 닫는 방향만** EMA(0.4) + 변화율 제한(15 mm/s).
   대칭으로 평활하면 사람이 갑자기 움직였을 때 명령이 뒤늦게 따라가고 그 지연 동안
   리프가 실제로 몸을 뭅니다. 평활은 떨림을 줄이려는 것이지 안전을 깎으라는 게
   아니므로 위험한 방향에만 겁니다.
   데드밴드 0.8 mm. 변화가 없어도 1초에 한 번은 보내야 워치독이 안 물립니다

## 6. 문제 해결

### 리프가 사람을 침범함 (몸이 있는 자리까지 내려옴)

가장 중요한 고장 모드입니다. 원인은 거의 항상 **마스크가 그 부위를 인체로 안 봤기**
때문이지, 리프 계산이 틀려서가 아닙니다. 계산은 리프 끝을 언제나
`인체 최상단 − 마진` 에 놓기 때문에 구조적으로 침범할 수 없습니다.

화면에서 **초록 윤곽선이 몸의 어디를 감싸고 있는지** 보세요. 윤곽선 밖으로 삐져나온
부위가 있으면 그 위로 리프가 내려옵니다.

| 증상 | 원인 | 대처 |
|---|---|---|
| 손가락·팔만 잘림 | 그 부위가 몸통과 끊어진 별개 덩어리인데 버려짐 | `b` 로 "가장 큰 덩어리만" 을 **끄세요** (기본은 꺼짐) |
| 몸 전체가 덜 잡힘 | 옷 때문에 표면 온도가 낮음 | `[` 로 최저 체온을 28도까지 내리세요 |
| 경계가 몸 안쪽에 그려짐 | 마진 부족 | `=` 로 마진을 올리세요 (기본 5 mm) |
| 사람이 움직일 때만 물림 | 명령 지연 | 이미 비대칭 평활로 막아 뒀습니다. 그래도 물리면 `MAX_RATE_MM_S` 를 올리세요 |
| `OVER` 표시가 뜸 | 인체가 조사야 경계를 넘어감 | 침범이 아닙니다. 리프를 끝까지 물려도 그 부위는 못 덮는다는 뜻입니다 |
| `SHUT` 인데 거기 몸이 있음 | 그 열의 인체 픽셀이 4 mm² 미만 | 온도 범위를 넓히거나 `b` 를 확인하세요 |

### 파이가 아두이노를 못 찾음

```bash
ls -l /dev/ttyACM* /dev/ttyUSB*      # 보이는가
dmesg | tail -20                      # 꽂을 때 뭐라고 나오는가
id -nG | grep dialout                 # 권한이 있는가 (없으면 usermod 후 재부팅)
sudo fuser -v /dev/ttyACM0            # 아두이노 IDE 시리얼 모니터가 잡고 있지 않은가
```

`Permission denied` → `sudo usermod -aG dialout $USER` 후 **재부팅**.
아두이노 IDE 의 시리얼 모니터가 열려 있으면 파이썬이 포트를 못 엽니다. 반드시 닫으세요.

### 포트는 열리는데 응답이 없음

`mlc_driver.py` 는 포트를 열 때 2.2초를 기다립니다. UNO 는 DTR 로 리셋되기 때문입니다.
그래도 `timeout waiting for reply to: PING` 이 나오면:

- 보드레이트가 115200 인지 (펌웨어와 같아야 합니다)
- 올라간 펌웨어가 정말 `AMLA_4CH_Positioning` 인지. 예전 `AMLA_MultiCH_NonBlocking`
  이 올라가 있으면 명령어 체계가 달라서(`1g30` 방식) 아무 응답도 안 옵니다
- 파이의 **검은 USB2 포트**로 옮겨 꽂아 보세요. 파란 USB3 쪽이 더 자주 말썽입니다

### 파이는 응답을 받는데 모터가 안 움직임

`mlc_driver.py /dev/ttyACM0 --test` 로 CH1~CH4 를 하나씩 흔들어 보세요.
**이 자가진단은 개루프입니다. 선이 빠져 있어도 펌웨어는 똑같이 완료를 보고합니다.
눈으로 본 것만 근거입니다.**

2026-08-27 에 하루를 잡아먹은 원인은 전부 배선이었습니다. 부품은 다 멀쩡했습니다.

- **빵판을 신호 경로에 두지 마세요.** 아두이노 → 드라이버 직결이 답입니다
- **겉보기 멀쩡한 점퍼선 단선이 2건 있었습니다.** 채널이 죽으면 부품 교체 전에
  두 선의 위치를 서로 맞바꿔 보세요. 증상이 따라오면 배선, 안 따라오면 코드입니다
- **한 방향으로만 움직이면 신호선 한 가닥이 끊긴 것입니다.** L298N 은 IN 하나가
  LOW 로 고정되면 그 방향이 정지(LOW/LOW)가 됩니다
- 아두이노 GND ↔ 각 드라이버 GND 를 **각각 직접** 연결하세요
- 12V 어댑터는 아두이노 USB 와 별도입니다. 파이 USB 로 모터를 돌릴 수는 없습니다

### 채널과 리프가 뒤바뀜

`--map` 으로 다시 짝지으면 됩니다. 배선을 다시 하지 마세요.

```bash
python3 run_row1.py --map 4,3,2,1     # CH1이 맨 오른쪽 열을 맡는 경우
```

### 열화상이 16비트로 안 열림

```bash
v4l2-ctl -d /dev/video0 --list-formats
```

`Y16` 이 없으면 다른 `/dev/videoN` 을 `--thermal` 로 지정하세요.
OpenCV 5.x 는 Y16 취득이 막힙니다. 4.x 로 맞추세요.
급하면 `--agc` 로 8비트 상대 밝기 모드로 돌릴 수 있습니다 (절대 온도 판정은 못 씀).

### 광카메라가 안 열림

```bash
rpicam-hello --list-cameras          # 인식 자체가 되는가
```

CSI 리본 방향(파란 면)을 확인하세요. picamera2 가 없으면
`sudo apt install -y python3-picamera2`. 광카메라 없이도 `--fusion off` 로
열화상만으로 돌아갑니다.

### VNC 로 PC 에서 볼 때

```bash
sudo raspi-config      # Interface Options -> VNC -> Enable
```

RealVNC Viewer 로 `raspberrypi.local:5900` 에 붙습니다. 7인치 화면이 그대로 미러링됩니다.
**중요: SSH 창에서 실행하지 말고, VNC 안의 터미널에서 실행하세요.** SSH 에는
`DISPLAY` 가 없어서 이 프로그램이 자동으로 헤드리스로 내려갑니다.
SSH 에서 굳이 띄우려면 `export DISPLAY=:0` 을 먼저 하세요.
화면 출력은 800×460 이라 7인치(800×480)에 딱 맞고 VNC 대역폭도 문제되지 않습니다.
