# MLC 코어 ↔ GUI 소켓 규약

GUI를 만드는 분이 읽는 문서입니다. 코어 프로그램이 완성되기를 기다릴 필요 없이,
**가짜 서버**를 상대로 지금 바로 화면을 만들 수 있습니다.

---

## 1. 왜 프로그램을 둘로 나눴나

한 덩어리로 만들 수 없는 이유가 세 가지 있습니다.

1. **GUI가 얼어도 리프는 닫혀야 합니다.** 화면과 구동이 같은 프로그램에 있으면
   화면이 멈출 때 리프가 열린 채로 남습니다.
2. **Kivy가 사는 `mp_env`의 cv2 5.0에서는 열화상의 절대 온도(Y16)를 못 읽습니다.**
   시스템 python3의 cv2 4.10에서만 열립니다. 실측으로 확인된 사항입니다.
3. **MediaPipe도 `mp_env`에만 있습니다.**

```
[코어]  시스템 python3               [GUI]  mp_env + Kivy
 열화상만 연다 (절대 온도)            광카메라만 연다 (MediaPipe)
 체온 판정 → 리프 계산        ←소켓→   화면 그리기 / 버튼
 아두이노 구동 + 워치독               열화상 "그림"은 코어에서 받는다
```

> ⚠️ **GUI는 열화상 장치를 직접 열면 안 됩니다.** 장치 하나를 두 프로세스가 열 수
> 없습니다. 열화상 그림이 필요하면 코어가 보내주는 JPEG를 쓰세요.

---

## 2. 붙는 방법

**TCP `127.0.0.1:9977`**, 한 줄에 JSON 하나(`\n`으로 끝남)입니다.

```python
import socket, json

sock = socket.create_connection(("127.0.0.1", 9977))
f = sock.makefile("rwb")

while True:
    state = json.loads(f.readline())     # 코어가 초당 10번 보냅니다
    print(state["open_mm"], state["flags"])
```

명령을 보낼 때도 같은 소켓에 한 줄씩 씁니다.

```python
f.write((json.dumps({"cmd": "motor", "on": True}) + "\n").encode())
f.flush()
```

여러 개가 동시에 붙어도 됩니다. GUI가 죽어도 코어는 계속 돕니다.

## 3. 개발용 가짜 서버

장비가 없어도, 파이가 없어도, 노트북에서도 됩니다.

```bash
python3 mlc_mock.py
```

진짜 코어와 **똑같은 규약**으로 말합니다. 리프가 사람이 좌우로 걸어다니는 것처럼
움직이고, `SHUT`·`OVER` 상태도 나오고, 열화상 미리보기 JPEG도 옵니다.
상태에 `"mock": true`가 들어 있으니 화면 어딘가에 표시해 두면 헷갈리지 않습니다.

나중에 이걸 끄고 진짜 코어를 켜면 **GUI는 고칠 것이 없습니다.**

## 4. 코어 → GUI (상태, 초당 10회)

```json
{
  "t": 1787581121.573,
  "motor": true,
  "manual": false,
  "link": true,
  "homed": [true, true, true, true],
  "aligned": true,
  "n_ch": 4,
  "travel_mm": 57.5,
  "open_mm": [0.0, 10.6, 44.6, 47.0],
  "act_mm":  [57.5, 46.9, 12.9, 10.5],
  "pos_mm":  [57.5, 46.9, 12.9, 10.5],
  "margin_mm": 5.0,
  "flags": ["SHUT", "", "", ""],
  "body_pct": 18.5,
  "temp": {"min": 22.6, "max": 33.2, "med": 24.1, "tmin": 28.0, "tmax": 200.0},
  "err": null,
  "jpeg": "<base64 JPEG, 초당 5회만>"
}
```

| 항목 | 뜻 |
|---|---|
| `motor` | 모터 출력이 켜져 있는가 |
| `manual` | 사람이 직접 지정한 값으로 도는 중인가 (false면 카메라가 정함) |
| `link` | 아두이노가 붙어 있는가 |
| `homed` | 채널별 원점 인식 여부. 하나라도 false면 위치를 못 믿습니다 |
| `aligned` | 조사야 4점 보정이 되어 있는가 |
| **`open_mm`** | **조사야가 얼마나 열려 있는가 [mm].** 화면에 보여줄 값은 이것입니다 |
| `act_mm` | 액츄에이터 목표 위치 [mm] (= `travel_mm − open_mm`) |
| `pos_mm` | 아두이노가 보고한 현재 위치. `null`이면 아직 모름 |
| `flags` | 열별 상태 (아래) |
| `body_pct` | 화면에서 인체로 잡힌 넓이 비율 [%] |
| `jpeg` | 열화상 미리보기. **매번 오지 않습니다**(초당 5회). 없으면 직전 것을 유지하세요 |

### 개방과 액츄에이터는 반대 방향입니다

```
open_mm  0.0  = 조사야 완전 차폐  →  act_mm 57.5 (로드 최대 전진)
open_mm 57.5  = 조사야 완전 개방  →  act_mm  0.0 (로드 완전 수축)
```

**화면에는 `open_mm`을 쓰세요.** `act_mm`은 기계 쪽 숫자입니다.

### flags

| 값 | 뜻 | 화면 표시 제안 |
|---|---|---|
| `""` | 정상 | — |
| `"SHUT"` | 그 열에 인체가 없어 완전 차폐 | 회색 |
| `"OVER"` | 인체가 조사야 경계를 넘어감. 리프를 끝까지 물려도 그 부위는 못 덮음 | 주황 경고 |

## 5. GUI → 코어 (명령)

명령을 보내면 **그 소켓으로만** 응답이 옵니다.

```json
{"ok": true,  "cmd": "motor"}
{"ok": false, "cmd": "manual", "err": "ch 는 1~4"}
```

> 응답과 상태가 같은 줄 흐름에 섞여 옵니다. `"ok"` 키가 있으면 응답,
> 없으면 상태로 구분하세요.

| 명령 | 예 | 하는 일 |
|---|---|---|
| `ping` | `{"cmd":"ping"}` | 살아있는지 확인 |
| `motor` | `{"cmd":"motor","on":true}` | 모터 출력 on/off |
| `home` | `{"cmd":"home"}` | 원점 복귀 후 완전 차폐. **약 45초 걸립니다** |
| `stop` | `{"cmd":"stop"}` | 즉시 정지 + 모터 off |
| `shield` | `{"cmd":"shield"}` | 전 채널 완전 차폐 |
| `auto` | `{"cmd":"auto"}` | 카메라 판정으로 복귀 (수동 해제) |
| `manual` | `{"cmd":"manual","ch":2,"open_mm":20.0}` | 한 채널을 직접 지정 |
| `manual` | `{"cmd":"manual","open_mm":[0,20,20,0]}` | 네 채널을 한꺼번에 |
| `margin` | `{"cmd":"margin","v":5.0}` | 보호 마진 [mm] |
| `tmin_pct` | `{"cmd":"tmin_pct","v":84}` | 상위 16%를 인체로 본다 |
| `tmin` | `{"cmd":"tmin","v":28.0}` | 고정 온도 기준으로 전환 |
| `ffc` | `{"cmd":"ffc"}` | 열화상 기준 재설정 |

### UP / DOWN 버튼은 이렇게 만드시면 됩니다

```python
# 선택된 리프를 5mm 더 연다
cur = last_state["open_mm"][ch - 1]
send({"cmd": "manual", "ch": ch, "open_mm": cur + 5.0})
```

`manual`을 한 번이라도 보내면 카메라 판정이 멈추고 사람이 지정한 값으로 돕니다.
카메라로 되돌리려면 `{"cmd":"auto"}`를 보내세요.

## 6. 화면에 꼭 넣어야 할 것

1. **`pos_mm`은 실제 위치가 아닙니다.** 이 장치에는 위치 센서가 없어서, 아두이노는
   "몇 초 동안 전기를 넣었으니 여기 있을 것"이라고 계산할 뿐입니다. 전압이 처지면
   실제로는 덜 갔는데도 숫자는 목표값을 가리킵니다. 화면에 그대로 믿을 값처럼
   크게 띄우면 위험합니다.
2. **`homed`에 false가 있으면 위치를 못 믿습니다.** 크게 경고를 띄우세요.
3. **`link`가 false면 모터가 안 붙은 상태입니다.**
4. **`mock`이 true면 가짜 데이터입니다.** 실제 장비가 아니라는 표시를 남기세요.

## 7. 지금 하드웨어와 화면의 차이

설계하신 화면은 **2행 4열 8칸**인데, 지금 하드웨어는 **아두이노가 한 대뿐이라
상단 4칸만** 실제로 움직입니다. `n_ch`가 4로 오니 그 값에 맞춰 그리시면 되고,
아래 4칸은 비활성으로 두었다가 두 번째 아두이노를 붙일 때 켜면 됩니다.
